Qué es

Total.js Flow te deja dibujar en el navegador FlowStreams: diagramas de componentes conectados por mensajes, para automatización, integraciones e IoT. Esta edición mantiene todo lo que Flow ofrece y añade lo que una clase necesita: que cada alumno tenga un espacio propio, que el profesor lo vea todo y que las prácticas se repartan sin copiar y pegar.

Cada alumno, su espacioSolo ve y toca sus FlowStreams. Ni sabiendo el identificador de otro puede abrirlo.
El profesor lo ve todoLista completa, resumen del aula y acceso al editor de cualquier alumno para ayudarle.
Prácticas con un clicPrepara una plantilla y entrégala a grupos o a cada alumno.
Usuarios y grupos de OpenPlatformAltas, bajas, clases y permisos se gestionan en un único sitio.

Las reglas se comprueban en el servidor, en cada acción y en la conexión del editor. Esconder un botón no es seguridad, así que aquí no se esconde: se comprueba.

Además, cada FlowStream se ejecuta en su propio proceso (flowstream_worker : fork), de modo que un alumno no puede parar el trabajo de los demás.

Cómo se usa en un aula

Antes de la clase (profesor)

  1. Crea la práctica como cualquier FlowStream: componentes, variables y una descripción con el enunciado.
  2. En su menú elige Usar como plantilla. Las plantillas no las ven los alumnos.
  3. Abre Classroom (en el menú de la izquierda) y pulsa Asignar en la plantilla.
  4. Elige los grupos. Por defecto cada grupo recibe una copia compartida; con Una copia para cada alumno del grupo cada alumno recibe la suya, con el nombre plantilla · alumno, que solo él y tú veis.

La copia conserva el diseño, los componentes, las variables y la descripción, y empieza a funcionar sola. Si asignas de nuevo, no se repiten las copias que ya existen: sirve para cuando llegan alumnos nuevos.

Durante la clase

  • El alumno entra por OpenPlatform, abre Flow y trabaja en su copia. Puede crear más FlowStreams en sus grupos si tiene el permiso create.
  • Tú abres el resumen de Classroom: alumno, grupo, FlowStream (y de qué plantilla viene), estado, errores, mensajes y fecha del último cambio. Filtra por grupo, plantilla o texto y verás quién no ha empezado y quién está trabajando.
  • Desde el menú de cada fila puedes abrir el FlowStream de un alumno para ayudarle, restaurarlo desde la plantilla (su trabajo se sustituye por la plantilla) o quitarlo.

Después

Los FlowStreams de cada alumno se quedan guardados en su espacio. Tú puedes exportarlos para revisarlos.

Instalar con Docker

La imagen está publicada en el GitHub Container Registry y se construye sola en cada cambio de master, para amd64 y arm64 (sirve en un servidor, en un Mac con Apple Silicon o en una Raspberry Pi).

docker pull ghcr.io/totaljs-es/flowee
docker run -d --name flowee -p 8000:8000 \
  -v flowee-databases:/www/databases \
  -v flowee-flowstream:/www/flowstream \
  -v flowee-private:/www/private \
  ghcr.io/totaljs-es/flowee

Abre http://localhost:8000. Los tres volúmenes guardan los ajustes, los FlowStreams de la clase y los archivos privados, para que no se pierda nada al cambiar a una imagen más nueva.

Con Docker Compose

git clone https://github.com/totaljs-es/flowee.git
cd flowee
docker compose up -d

Actualizar

docker pull ghcr.io/totaljs-es/flowee
docker rm -f flowee
# y vuelve a lanzar el docker run de arriba: los volúmenes conservan los datos

Sin Docker

git clone https://github.com/totaljs-es/flowee.git
cd flowee
npm install
npm start          # puerto 8000

Necesitas Node.js 24.

Cuánta máquina necesitas. Cada FlowStream es un proceso independiente. Calcula la memoria para la clase más grande que trabaje a la vez y limítala con flowstream_memory.

Conectar con OpenPlatform

Flow EE funciona dentro de OpenPlatform: de allí vienen los usuarios, los grupos y los permisos.

  1. Registra Flow EE como aplicación en OpenPlatform. Su openplatform.json lo sirve la propia aplicación (http://tu-flow:8000/openplatform.json). Anota el request token y el response token que le des.
  2. Crea un grupo por cada clase (o por alumno, si quieres que el trabajo de cada uno sea privado incluso sin dueños).
  3. Da la aplicación a los grupos de alumnos y de profesores. Los usuarios con sa son los profesores.
  4. La aplicación ofrece dos permisos: create (crear Flows) y remove (quitarlos). Dale create a los alumnos.
  5. Abre Flow EE por primera vez, entra con la cuenta por defecto que enseña la página de acceso y, en los ajustes, pega los dos tokens. A partir de ahí los usuarios entran por OpenPlatform.
  6. Opcional: activa la API pública de usuarios en OpenPlatform y pon su dirección en op_groups. Hace falta para la opción una copia para cada alumno.

OpenPlatform en la nube

Si usas un OpenPlatform en la nube, pon su dirección en sso en el archivo config. El acceso se verifica allí y los grupos y el profesor (sa) salen de su sesión. En esta edición nadie puede hacerse pasar por otros grupos: el profesor sigue siendo el profesor.

Configuración

El archivo config trae los ajustes habituales de Flow y estos:

AjustePara qué sirve
op_groupsDirección de la API de usuarios de OpenPlatform (https://mi_openplatform/users/?token=[]). Necesaria para una copia por alumno; sin ella, una plantilla se copia una vez por grupo.
ssoDirección de un OpenPlatform en la nube para el acceso.
flowstream_workerfork (por defecto aquí): cada FlowStream en su proceso.
flowstream_memoryMemoria máxima en MB de cada FlowStream (0 es automático). Recomendado en clase.
$proxytimeoutTiempo máximo del proxy de los FlowStreams, en segundos.

Datos y privacidad

Todo se queda en tu servidor: los FlowStreams, las copias de los alumnos y los ajustes viven en los volúmenes de Docker (databases, flowstream, private). El trabajo de los alumnos no sale de tu servidor.

A cada FlowStream esta edición le añade estas propiedades: group (el grupo de OpenPlatform), ownerid y ownername (el alumno), template (si es plantilla) y templateid (la plantilla de la que viene una copia).

Los textos de Flow que no tengan traducción al español se muestran en inglés. La interfaz sigue el idioma del usuario en OpenPlatform.

Novedades de la versión 2.1

  • Al día con Total.js Flow 11.1: jComponent actualizado y arreglo al arrastrar componentes.
  • Acceso con OpenPlatform en la nube (sso), sin que nadie pueda suplantar grupos.
  • Una plantilla de un grupo es solo para los profesores: los alumnos del grupo ya no la ven ni la editan.
  • La imagen Docker se construye desde el código, sin bundles que mantener, y guarda sus datos en /www/databases, /www/flowstream y /www/private.
  • 47 comprobaciones automáticas (npm test) con un OpenPlatform de pruebas: profesor, tres alumnos, copias, restauración y privacidad entre compañeros.
