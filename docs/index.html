Flow, prepared for teaching

Total.js Flow lets you draw FlowStreams in the browser: diagrams of components connected by messages, for automation, integrations and IoT. This edition keeps everything Flow offers and adds what a class needs.

Every student, their own place

Students only see and touch their own FlowStreams. Not even knowing the identifier of another one lets them open it.

The teacher sees everything

The full list, an overview of the class and access to the editor of any student to help them.

Practices with one click

Prepare a template and hand it out to groups or to each student.

Users and groups from OpenPlatform

Sign-ups, classes and permissions are managed in one place.

What changes compared to Flow

The rules are checked on the server, in every action and in the connection of the editor. Hiding a button is not security, so nothing is only hidden: it is checked.

Teacher (user sa)Student
FlowStreams in the listAllThose of their groups and, if a FlowStream has an owner, only their own
Create a FlowStreamIn any group or without a groupOnly in their groups, with the create permission
Edit, run, pause, restart, export, removeAnyOnly their own (remove needs the permission)
Editor and variables of a FlowStreamAnyOnly their own
Code of the components (read, edit, remove)YesNo: they work with the components of the palette of their group and of the template
Import FlowStreamsYesNo. They can duplicate their own FlowStream
Global variables, settings, console, CDN cacheYesNo
Classroom panel (templates and overview)YesNo
TemplatesSees and manages themDoes not see them, even in their group

Every FlowStream also runs in its own process (flowstream_worker : fork), so a student cannot stop the work of the others.

How it is used in a classroom

Before class you prepare the practice; during class you follow the work of everyone.

Build the practice

Build the exercise as any FlowStream: components, variables and a description with the instructions. In its menu choose Use as template. Students never see templates. In Component palette choose which components each group has: students cannot add or edit them.

Hand it out

Open Classroom in the left menu and press Assign. Every group gets one shared copy, or choose One copy for each student: each one gets their own, named template · student, visible only to them and to you. Assigning again does not repeat copies: use it when new students arrive.

Follow the class

The overview shows student, group, FlowStream, status, errors, messages and last change. Filter by group, template or text to see who has not started. From each row you can open a student’s FlowStream to help, restore it from the template or remove it.

A copy keeps the design, components, variables and description of the template, and starts running by itself. Students enter through OpenPlatform, open Flow and work on their copy; they can create more FlowStreams in their groups if they have the create permission.

Install it with Docker

The image is published in the GitHub Container Registry and is built automatically for amd64 and arm64: a server, an Apple Silicon Mac or a Raspberry Pi. Node.js 24, nothing else to install.

Run it

docker pull ghcr.io/totaljs-es/flowee
docker run -d --name flowee -p 8000:8000 \
  -v flowee-databases:/www/databases \
  -v flowee-flowstream:/www/flowstream \
  -v flowee-private:/www/private \
  ghcr.io/totaljs-es/flowee

Open http://localhost:8000. The three volumes keep the settings, the FlowStreams of the class and the private files when you move to a newer image.

Docker Compose

git clone https://github.com/totaljs-es/flowee.git
cd flowee
docker compose up -d

The same thing, with the volumes already declared.

Update it

docker pull ghcr.io/totaljs-es/flowee
docker rm -f flowee
# run the docker run above again

The volumes keep the data. Without Docker: npm install and npm start (Node.js 24).

How much machine? Every FlowStream is an independent process. Plan the memory for the largest class working at the same time and limit it with flowstream_memory.

Connect it to OpenPlatform

Flow EE works inside OpenPlatform: users, groups and permissions come from there.

Register the app

Add Flow EE to OpenPlatform as an application; the app serves its own openplatform.json (http://your-flow:8000/openplatform.json). Write down the request token and the response token you give it.

Groups and permissions

Create a group for each class and give the app to the groups of students and teachers. Users with sa are the teachers. Give students the create permission (and remove if they may delete).

Paste the tokens

Give the two tokens to Flow EE as FLOWEE_OP_REQTOKEN and FLOWEE_OP_RESTOKEN or, the first time, sign in with the default account shown on its login page and paste them in the settings. From then on users enter through OpenPlatform.

Optional: enable the public users API in OpenPlatform and put its address in op_groups; it is needed for one copy for each student. With OpenPlatform in the cloud put its address in sso in config: sign-in is verified there and groups and teacher come from its session. Nobody can impersonate groups.

SettingWhat it does
op_groupsAddress of the OpenPlatform users API (https://my_openplatform/users/?token=[]). Needed for one copy per student; without it a template is copied once per group.
ssoAddress of an OpenPlatform in the cloud for the sign-in.
flowstream_workerfork (default here): each FlowStream in its own process.
flowstream_memoryMaximum memory in MB of each FlowStream (0 is automatic). Recommended in class.
$proxytimeoutTimeout of the FlowStreams proxy, in seconds.

No files to edit. Every setting also works as an environment variable: FLOWEE_ plus the key in upper case (FLOWEE_SSO, FLOWEE_OP_GROUPS, FLOWEE_FLOWSTREAM_MEMORY…), and the same goes for the two tokens of the application (FLOWEE_OP_REQTOKEN, FLOWEE_OP_RESTOKEN). The docker-compose.yaml already lists them all.

Everything included
